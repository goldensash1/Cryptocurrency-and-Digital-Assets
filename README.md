# ALU Logo Registry dApp (Assignment 2)

A browser application (dApp) for the two Formative 1 smart contracts:

- **`ALUAssetRegistry`** (ERC-721) stores the SHA-256 fingerprint of the official ALU logo, who registered it and when.
- **`ALULogoToken`** (ERC-20, symbol ALUT) splits ownership of the logo into 1,000,000 shares.

The contracts are unchanged from Formative 1 (they had no bugs; all 8 original tests still pass). The new work is the `frontend/` folder, an updated `scripts/deploy.js`, and 5 new tests.

## How the dApp works

There are three pages in one site, all with the **Connect Wallet** button in the header.

| Page | Needs wallet? | What it does | Contract calls |
|---|---|---|---|
| **Verify** (`#/verify`) | No | Upload an image (or paste a hash). The browser hashes it, then the page says "Logo Verified" (green) or "Warning: This logo has been modified" (red). If authentic it shows the registered name, date and wallet. | `ALUAssetRegistry.verifyLogoIntegrity()`, `getAsset()` (read-only, free) |
| **Register** (`#/register`) | Yes | Choose an image, see the preview and its SHA-256 hash (bytes32), fill in name and type, approve in the wallet. Shows the new token ID, or a clear message if the hash is a duplicate. | `ALUAssetRegistry.registerAsset()` (transaction), `hashRegistered()` |
| **Dashboard** (`#/dashboard`) | To see your own balance / to send | Total supply, your balance and ownership %, a table of holders with percentages, and an owner-only form to send shares. | `ALULogoToken.totalSupply()`, `balanceOf()`, `ownershipPercentage()`, `owner()`, `distributeShares()` |

### How the frontend connects to each contract

1. `scripts/deploy.js` deploys both contracts and writes `frontend/js/deployment.js`, which holds the **contract addresses, the ABIs** (read from Hardhat's build output), the network and the example holder wallets.
2. `frontend/js/app.js` creates two kinds of ethers.js `Contract` objects from that file for each contract:
   - **read-only** objects on a plain JSON-RPC provider (used by the Verify page and all balance reads, so no wallet is needed and no gas is spent);
   - **write** objects on the user's wallet **signer** (used by Register and Distribute, so the wallet pops up and the user approves each transaction).
3. `frontend/js/alu.js` holds all the logic (hashing, verify, register, balances, distribute). It has no page code, so the Hardhat tests import and run the exact same functions the browser runs.

```
frontend/
  index.html          page layout (3 pages + header)
  css/style.css       styling (light/dark)
  js/alu.js           logic: hashing, verify, register, balances, distribute (also used by tests)
  js/app.js           screens, wallet connection, network switching
  js/deployment.js    GENERATED by deploy.js: addresses + ABIs + network
  vendor/ethers.umd.min.js   ethers v6.17.0 (bundled so no CDN is needed)
  server.js           tiny static server (no dependencies)
```

## Install and run

You need three terminals in the project folder.

```bash
npm install
```

```bash
npx hardhat node
```
Terminal 1: local blockchain with 20 funded test wallets. Leave it running.

```bash
npx hardhat run scripts/deploy.js --network localhost
```
Terminal 2: deploys both contracts, registers the logo (token 1), gives demo shares to Hardhat accounts #1-#3 (250,000 / 150,000 / 100,000 ALUT; the owner keeps 500,000) and writes `frontend/js/deployment.js`. **Run this again every time you restart `hardhat node`** (the chain forgets everything when it stops).

```bash
npm run frontend
```
Terminal 3: opens the site at http://localhost:3000 (same as `node frontend/server.js`).

Run the tests with `npx hardhat test` (13 tests: 8 from Formative 1 + 5 new).

## Connecting a wallet and using each feature

1. Install **MetaMask** (or Coinbase Wallet; any wallet that injects `window.ethereum` works).
2. In MetaMask add a network: RPC `http://127.0.0.1:8545`, chain ID `31337`, currency ETH. (If you forget, the dApp shows a "Switch network" button that adds it for you.)
3. Import the owner account: MetaMask > Import account > paste the private key of Hardhat account #0 printed by `npx hardhat node` (these are public test keys with fake ETH; never use them on a real network).
4. Open http://localhost:3000 and click **Connect Wallet**. You will see your shortened address and ALUT balance. **Disconnect** forgets the account in the app.
5. **Verify**: choose `alu-logo.png` (green "Logo Verified") and then any other or edited image (red warning). Or paste the hash above. Works without a wallet.
6. **Register**: choose a new image, check the preview and hash, edit name/type, click Register, approve in the wallet. Choosing `alu-logo.png` again shows the duplicate message.
7. **Dashboard**: shows supply, your balance and ownership %, and the holder table. Connected as account #0 (the owner) you can send shares; any other account sees the form disabled with an explanation.

## Deploy to the Sepolia testnet

1. Create a new MetaMask account used only for this project, switch it to Sepolia and get free test ETH from a faucet.
2. Copy `.env.example` to `.env` and put that account's private key in `SEPOLIA_PRIVATE_KEY`. Never commit or share `.env`.
3. Run `npx hardhat run scripts/deploy.js --network sepolia`. This also rewrites `frontend/js/deployment.js` for Sepolia (chain 11155111), so `npm run frontend` then talks to the testnet.

## Tests

`test/ALUAssetRegistry.test.js` has 13 tests.

- Tests 1-8 are the Formative 1 contract tests (5 registry, 3 token).
- Tests 9-13 are the frontend integration tests, calling `frontend/js/alu.js` against freshly deployed contracts: (9) total supply read and shown as `1,000,000`; (10) hashing a file returns the correct bytes32 SHA-256; (11) success result for the correct hash; (12) failure result for a wrong hash; (13) `distributeShares` updates the recipient's balance.

## Known issues and limitations

- **Not deployed to a public testnet yet.** The code and `.env.example` support Sepolia, but I did not have a funded Sepolia key in this environment, so the tested deployment is the local Hardhat chain. Follow the Sepolia steps above to deploy.
- The Hardhat chain resets when stopped; re-run the deploy script and refresh the page.
- The wallet pop-up and MetaMask itself were not driven by the automated browser run: in my browser tests I used a stand-in wallet object that forwards to Hardhat's unlocked accounts. All contract calls, validation and UI states are real; the actual MetaMask approval screen should be checked manually (steps above).
- Hash/verification works on the exact bytes of a file. Re-saving or re-compressing an image changes its hash, so a "re-exported" logo is reported as modified. This is intended.
- `ownershipPercentage()` returns whole percents (integer division), so a holder with under 1% shows 0%. The dashboard also shows the exact figure.
- Anyone can register any new hash (as in Formative 1); only the logo at token ID 1 is "official". The Verify page checks against token ID 1.
- Disconnect only forgets the account inside this site; MetaMask itself still lists the site as connected until you remove it in MetaMask.
- Tested in Chromium-based browsers only.

## Problems encountered and fixes (Formative 1 notes kept)

- `npm install` failed with an `ERESOLVE` peer-dependency error because `hardhat-toolbox` needed a newer Hardhat 2.x than the one first pinned. Fix: install `hardhat@^2.28`. Always install Hardhat locally; `npx hardhat` without a local install pulls Hardhat 3, which has a different config format.
- First compile appears to hang while Hardhat downloads the 0.8.28 compiler.
- Assignment 2: the error text from a reverted transaction differs between wallets (MetaMask, RPC, ethers), so `friendlyError()` in `alu.js` maps the common cases (duplicate hash, not owner, insufficient balance, rejected in wallet) to plain sentences, and the app pre-checks duplicates with `hashRegistered()` before asking for a signature.
- ALUT uses 0 decimals so "1,000,000 tokens" is exactly 1,000,000 base units and percentages are exact whole numbers.
